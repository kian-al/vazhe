# واژه

واژه وب‌اپ فارسی‌محور یادگیری واژگان انگلیسی است (Next.js، React، TypeScript و PostgreSQL). رابط صفحهٔ اصلی و کتابخانه از طراحی ارسالی اقتباس شده‌اند.

## اجرای محلی

### ۱. پیش‌نیازها و دریافت کد

- Git و Node.js نسخهٔ ۲۰٫۹ یا بالاتر به‌همراه npm نصب باشند. Node.js 24 هم قابل استفاده است.
- برای بررسی تغییرات حساب، شاخهٔ در حال توسعه را دریافت کنید:

```sh
git clone https://github.com/kian-al/vazhe.git
cd vazhe
git switch wip/account-data-foundation
npm ci
```

اگر مخزن را قبلاً دریافت کرده‌اید، در پوشهٔ آن ابتدا `git fetch origin` و سپس `git switch wip/account-data-foundation` را اجرا کنید. تغییرات ذخیره‌نشدهٔ خود را پیش از تعویض شاخه بررسی کنید.

### ۲. تنظیم محیط

برای دیدن رابط، می‌توانید بدون تنظیم دیتابیس هم برنامه را اجرا کنید؛ در این حالت ذخیره‌سازی سروری و سرویس حساب کار نمی‌کنند. برای اتصال واقعی به سرویس‌ها، فایل تنظیمات محلی بسازید:

```sh
cp .env.example .env.local
```

در ویندوز PowerShell به‌جای دستور بالا از `Copy-Item .env.example .env.local` استفاده کنید. فایل `.env.local` را ویرایش کنید:

- `DATABASE_URL`: رشتهٔ اتصال یک دیتابیس PostgreSQL **آزمایشی و جدا از production**، سازگار با Neon.
- `NEON_AUTH_BASE_URL`: آدرس Neon Auth مربوط به همان محیط آزمایشی، پس از فعال‌کردن Auth برای آن.
- `NEON_AUTH_COOKIE_SECRET`: یک مقدار تصادفی محرمانه با حداقل ۳۲ نویسه؛ برای نمونه با `openssl rand -hex 32` بسازید و خروجی را فقط در فایل محلی قرار دهید.
- `APP_ORIGIN`: اختیاری؛ برای اجرای عادی محلی می‌توانید خالی بگذارید. اگر مقدار می‌دهید، باید دقیقاً با مبدأ برنامه، مثلاً `http://localhost:3000`، مطابقت داشته باشد.

نشانی دیتابیس و Auth آزمایشی را از تنظیمات Neon همان محیط بگیرید؛ استفاده از آدرس و رمزهای production برای تست محلی مجاز نیست. اجازهٔ `localhost` باید در تنظیمات Auth آزمایشی فعال باشد. فایل `.env.local` و مقادیر محرمانه را در Git ثبت نکنید یا در چت نفرستید. پس از تغییر متغیرها، سرور محلی را دوباره اجرا کنید.

اگر دیتابیس آزمایشی **تازه و خالی** است، برای آماده‌سازی دستی ساختار و داده‌های آن دستورات زیر را یک‌بار اجرا کنید. این دستورات روی دیتابیس تنظیم‌شده در `.env.local` می‌نویسند؛ قبل از اجرا حتماً مطمئن شوید محیط آزمایشی است. برای دیتابیس ازپیش‌آماده، از اجرای بی‌دلیل آن‌ها خودداری کنید:

```sh
npm run db:migrate
npm run db:seed
npm run books:migrate
npm run books:seed
```

مهاجرت و ورود داده‌ها بخشی از build نیستند. جزئیات کتاب‌ها و داده‌ها در [BOOKS-AND-DEPLOYMENT.md](BOOKS-AND-DEPLOYMENT.md) است.

### ۳. اجرای نسخهٔ توسعه

```sh
npm run dev
```

در مرورگر [http://localhost:3000](http://localhost:3000) را باز کنید؛ صفحهٔ حساب در [http://localhost:3000/account](http://localhost:3000/account) است. برای توقف سرور در ترمینال `Ctrl+C` بزنید.

آدرس [http://localhost:3000/api/health](http://localhost:3000/api/health) وضعیت دیتابیس و واژه‌نامه را نشان می‌دهد: `local` یعنی دیتابیس تنظیم نشده، `ready` یعنی اتصال و داده‌های واژه‌نامه آماده‌اند، و `needs-seed` یا `unavailable` نیاز به بررسی دارند. [http://localhost:3000/api/library](http://localhost:3000/api/library) هم وضعیت کتابخانه را نشان می‌دهد.

### ۴. تست دستی build پیش از مرج

در پوشهٔ پروژه، پس از توقف `npm run dev`، جداگانه اجرا کنید:

```sh
npm run typecheck
npm test
npm run build
npm start
```

سپس [http://localhost:3000](http://localhost:3000) را باز کنید و با **داده و حساب آزمایشی** جریان‌های موردنظر را بررسی کنید. `npm start` خروجی آخرین build را اجرا می‌کند؛ در پایان با `Ctrl+C` آن را متوقف کنید. تست‌ها دستی و جدا از build و CI هستند.

**وضعیت شاخهٔ حساب:** رابط ثبت‌نام، ورود، تأیید ایمیل و بازیابی رمز در حال توسعه است. اتصال واژه‌ها به حساب هنوز کامل نیست، همگام‌سازی بین دستگاه‌ها فعال نشده و کل جریان با سرویس ایمیل واقعی تأیید نشده است. بنابراین اجرای محلی یا دیدن این فرم‌ها به‌معنای آماده‌بودن حساب نیست. تا تکمیل کار، از دادهٔ واقعی برای آزمون استفاده نکنید. جزئیات در [docs/ACCOUNT-IMPLEMENTATION.md](docs/ACCOUNT-IMPLEMENTATION.md) آمده است.

## محصول و محدودیت‌ها

- مطالعهٔ آزاد همهٔ واژه‌ها را پوشش می‌دهد و مرحله یا موعد را تغییر نمی‌دهد. مرور زمان‌بندی‌شده در کد با FSRS-6 برای دستهٔ فعال جداست؛ دسته حداکثر ۱۰۰ واژه دارد.
- دادهٔ مهمان روی سرور و نسخهٔ پشتیبان محلی نگهداری می‌شود؛ هویت وابسته به کوکی مرورگر است، نه حساب قابل بازیابی یا همگام‌سازی چنددستگاهی. از وضعیت ذخیره و خطا غافل نشوید.
- کتابخانهٔ کلاسیک از متون گوتنبرگ واژه استخراج می‌کند؛ فهرست درس کتاب‌های تجاری بدون منبع و مجوز وارد نشده است. جزئیات و روش در سند کتابخانه است.
- مربی هوشمند واقعی و اپ بومی iOS و Android در این نسخه نیستند. نسخهٔ افزونه آزمایشی است. سرویس‌های رایگان سقف مصرف دارند.
- انتساب واژه‌نامه و مجوز در [data/NOTICE.md](data/NOTICE.md)؛ دادهٔ بسته‌بندی‌شده در `data/dictionary-part-*.b64` است.

## استقرار

Vercel از `npm ci` و `npm run build` استفاده می‌کند و فقط شاخهٔ main برای استقرار خودکار فعال شده است. مرج به main و همچنین push مستقیم به main باعث استقرار می‌شود؛ این امر فقط پس از اتصال واقعی مخزن به پروژهٔ Vercel عمل می‌کند. تنظیمات، حقوق داده و محدودیت‌ها را در [BOOKS-AND-DEPLOYMENT.md](BOOKS-AND-DEPLOYMENT.md) بخوانید.

برای کار حساب، PR تا زمان تکمیل draft می‌ماند. پیش از مرج یا انتشار، یک build یا preview با محیط آزمایشی در اختیار مالک قرار می‌گیرد تا آن را شخصاً تست کند؛ تنها پس از تأیید صریح او، دربارهٔ مهاجرت و مرج هماهنگ می‌شود. این یک مرحلهٔ توافق‌شدهٔ دستی است و به‌تنهایی قفل یا branch protection خودکار ایجاد نمی‌کند.
